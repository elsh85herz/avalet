# Spec sync in review mode: plan (private, delete before going public)

Task: `CLOUD_TASK_5.md`. Review mode (`review`) learns to take the specification
being discussed, collect decisions on it and turn the confirmed ones into
patches the analyst previews and applies. No new meeting mode.

## What exists (read on 2026-09-30, `f711314`)

- `MODE_INSTRUCTIONS.review` (live prompt): remarks as `Замечание: раздел X, суть, кто сказал`, decisions as `Решение: ...`. The overlay board (`MODE_BOARD.review`) collects remarks and decisions from the finished suggestions, no extra call.
- `MODE_SUMMARY.review`: headings `Обсуждения`, `Замечания к документу`, `Решения по открытым вопросам`, `Поручения и сроки`, `Новые вопросы и риски`. The summary call returns text, then `@@AVALET_JSON@@` and `{agenda, actions}`; `mergeSummaryAnalysis` keeps hand-set marks.
- The briefing (`sessionContext`) goes capped (3,500 chars) into every live call and in full into the summary as REFERENCE ONLY.
- Meetings are one JSON file each (`meetings-store.ts`); exports go through `chooseSavePath` (save dialog; E2E writes to the test folder).
- The old agenda-file import used `<input type=file>` and `file.text()` in the renderer: no new IPC, no path handling in main. Reused for the artifact.
- `QuoteRef` + `locateQuote` (CLOUD_TASK_4): a quote is kept only when found in the transcript; `at` comes from the transcript, not from the model.

## Decisions

1. **Where the artifact lives.** Its own fields, not glued into the briefing: settings `artifactName` + `artifactText` (set before Start), copied onto `Meeting.artifact = {name, text}` at Start when the mode is `review` (also when the mode is switched to `review` during a call and the meeting has none). Reason: the briefing is reference-only and capped for live calls; the artifact is the thing being edited, needs the full text at the end and must never be cut. Not copied onto meetings of other modes (the document stays where it is used).
2. **Settings snapshot carries only name and size**, the text goes through `avalet:artifact-get` / `avalet:artifact-set`. Reason: the snapshot is fetched often and by both windows; 200 KB each time is waste.
3. **Size cap: 200,000 characters, hard.** Above it `artifact-set` refuses and the field says to load the relevant part. Reason: task rule; also 200 k chars (~67 k tokens) plus a 120 k-char transcript still fits the large-context providers. Highlight the cost above 60,000 chars.
4. **Editable before Start only.** The field is read-only while a meeting runs; `artifact-set` refuses during a running meeting. After the call a review meeting without an artifact can still get one from the Decisions panel ("Load document"), so a forgotten file is not a dead end.
5. **Characters per token: 3.** Used for every rough figure in the warnings. Reason: Russian text on current tokenizers is about 2.5-4 chars per token; 3 is the middle and matches the mock server. Figures are rounded and shown as "about".
6. **Live suggestions get an index, never the text.** Built in code (`electron/artifact-index.ts`): heading tree with section numbers (the document's own numbers when the heading has them, else computed 1, 1.1, ...), first line of each section (cut to 100 chars), plus an "Открытые вопросы / Open questions" section verbatim (cut to 1,500 chars). Whole index capped at 4,000 chars. Test: a 100,000-char artifact keeps the live system prompt under a fixed bound.
7. **A typed question naming a section** ("раздел 3.2", "section 3.2", "п. 3.2") in review mode with an artifact gets that one section's text added to that one question (cut to 4,000 chars). Optional and only on an explicit ask; the field's cost note says so before Start.
8. **Live prompt.** One added paragraph in `MODE_INSTRUCTIONS.review`: address sections by the index numbers; a proposal becomes `Предложение: раздел X, суть, кто сказал`; `Решение: ...` only after clear agreement. `MODE_BOARD.review` = remarks, proposals, decisions.
9. **Decision shape** (`Decision` in the IPC contract): `id`, `text` (edit instruction), `status` (`accepted | proposed | rejected | open`), `by`, `section`, `before`, `after`, `include` (the checkbox), QuoteRef (`quote`, `speaker`, `at`), `manual` (edited by hand), `removed` (deleted by hand, kept as a tombstone so a re-summarize does not bring it back), `ungrounded` (the model gave a quote that is not in the transcript).
10. **Grounding backstop in code.** The quote is looked up with `locateQuote`; `at` is taken from the transcript. An `accepted` decision whose quote is missing or not found is kept but `ungrounded`, its checkbox starts off and the row says "quote not found in the transcript, check". Reason: the owner's trust rule (decisions only from what was said) gets a check that does not depend on the model obeying the prompt.
11. **Section is never invented.** A `section` that does not match an index number or heading becomes `не определён`.
12. **Merge on re-summarize.** Rows edited by hand (`manual`) and deleted rows stay as they are; a fresh decision that matches one of them (same normalized text) is dropped; other fresh ones are added with `include = accepted && grounded`.
13. **Patches are addressed by an exact anchor.** Model returns `{patches:[{decisionId, op, anchor, text}], skipped:[{decisionId, reason}]}`. Code (`electron/artifact-patch.ts`, pure) finds the anchor: exact, then trimmed; must occur exactly once. Positions are computed on the original; overlapping patches: the later one is not applied ("overlap"). Applied from the end so offsets stay valid. CRLF documents: the anchor and text are converted to CRLF before searching and inserting. `insert_after` puts a line break first when the anchor ends a line and the text does not start with one; `delete` of a whole line takes its line break too. Everything outside the patched ranges is byte-identical (tested).
14. **Undo.** The original stays on the meeting; applying means "original + the checked patches", so unchecking a patch and applying again undoes it; "Back to the original" drops the result.
15. **Preview first, always.** "Update the document" asks for confirmation with the estimated tokens, then shows every patch (old fragment, new fragment, checkbox) and the not-applied / skipped ones with reasons. Nothing is written until "Apply".
16. **Stored on the meeting:** `artifactProposal` (patches with their check results, skipped, when) and `artifactResult` (`{text, patchIds, at}`), so the preview and the result can be re-opened.
17. **Usage purpose `"artifact"`**, same balance as the summary, no new paywall; access problems go through the existing paywall path.
18. **Warnings (plain words, a rough figure, before the spend):** (a) the artifact field before Start: the document goes to the model twice at the end, about N tokens each, and the index adds about M tokens to every live suggestion; (b) next to "Summarize" for a review meeting with a document: the summary request is about N tokens bigger; (c) the confirmation before "Update the document": document + decisions + expected reply. All three from one pure module (`src/renderer/lib/artifact-cost.ts`), which returns nothing for other modes or without a document (tested).
19. **Exports:** updated document (`.md`, exactly the computed text, no header) + Copy; decisions (`.md`, fixed headings, checked decisions and the protocol's action points). Existing exports unchanged.
20. **Not done here:** the summary text and the structured decisions are made consistent by the prompt only (every accepted decision under `Решения по открытым вопросам`); no code rewrites the model's text. A mismatch shows as a missing line, never as an invented one.
