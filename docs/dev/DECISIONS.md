# Decisions (task scaffolding, delete before going public)

One line each: decision, reason.

- IPC types live in `electron/shared/ipc-contract.ts` (types, `InvokeMap`, `EventMap`, `AvaletApi`, runtime channel list); preload, renderer and main import it. Reason: one source of truth; preload's `api: AvaletApi` and typed `invoke()` make drift a compile error (verified by deleting a method: tsc fails).
- `electron/main.ts` split into `app-core.ts` (all non-window IPC handlers, testable) and a thin Electron shell; `WINDOW_CHANNELS` lists what main.ts keeps. Reason: integration tests need the real handlers without Electron.
- Stores (`settings`, `history`, `meetings`, `log`, paths) take their backend via `init*()` instead of importing Electron. Reason: run under plain `node --test`.
- `wip/model-manager` (8aeb1ae) was ported by hand, not cherry-picked. Reason: it edits the three duplicated type files this step removes and the settings panel that changed since; the logic (local-only load, download step, Start blocked when missing) is kept.
- Model state and progress are computed in TypeScript from the Hugging Face cache folder, not by the sidecar. Reason: works when the recognizer is not running, testable with temp dirs.
- Download runs as a separate process (`server.py --download <model>`), not a thread in the sidecar. Reason: Cancel = kill; a Python thread cannot be stopped.
- Downloads set `HF_HUB_DISABLE_XET=1`. Reason: plain HTTP writes a growing `.incomplete` file, which is what progress measures.
- "Old and new HF cache layouts" = current (blobs + snapshot symlinks, `blobs/*.incomplete`) and legacy/no-symlink (real files in `snapshots/<rev>/`, `*.incomplete` next to them). Progress counts each regular file once, never following links.
- Failed download: 2 automatic retries (3 s, 10 s), partial file kept so retries and "Continue" resume. Reason: covers short network drops without user action.
- Delete model is shown in both levels (rc.2; was Advanced only). Reason: CLOUD_TASK_2 step 2 asked for download, cancel, resume and delete in Simple Settings; kept for the single model of CLOUD_TASK_4 (frees 0.5 GB, and is how to force a fresh download).
- Live checklist setting: stored `null` = level default (Advanced on, Simple off); an explicit choice wins. Toggle only in Advanced settings. Reason: CLOUD_TASK step 1.
- Checklist pacing now counts from the meeting start (no call in the first 30 s; 90 s ceiling applies to the first call). Reason: before, the first 80 characters triggered a call immediately because `lastRunAt` started at 0.
- API keys are refused when OS encryption is unavailable (was: stored base64 in the clear as a "dev fallback"). Reason: key handling; E2E on Linux uses `--password-store=basic`.
- Main window now `sandbox: true`, navigation and `window.open` locked (http(s) links go to the system browser). Reason: IPC/renderer hardening; preload only needs `electron`.
- Tests are collected by `scripts/run-tests.mjs` instead of a hand-written list in package.json. Reason: new test files cannot be forgotten.
- Background (checklist) model defaults: Claude `claude-haiku-4-5`, OpenAI `gpt-4.1-mini`, DeepSeek `deepseek-flash`, custom = main model. Reason: cheaper class for background work (Step 2 requirement, needed by the tracker now).
- `generate()` now returns `{text, usage}`; OpenAI-compatible streams send `stream_options.include_usage`; a server that rejects it (400 mentioning stream_options) is retried once without it. Reason: real counts from every provider that supports them, no breakage on old local servers.
- Local token estimate (3 chars per token, 1000 per image) is used only when a response has no usage, and every such call is flagged `estimated`. Reason: CLOUD_TASK "no local estimation except as a labeled fallback".
- A stream aborted after some output is recorded as an estimate; a call that failed before any output is not recorded. Reason: aborted streams are still billed by providers.
- Weight table in `electron/metering/model-weights.ts`: flash-class x1 (haiku, mini, nano, flash, lite, avalet-fast), premium x4 (opus, sonnet, gpt-4.1, gpt-5, pro, large, avalet-premium); unknown models x4. Reason: never under-count a budget.
- Ledger keeps running totals (per month and tier, trial, last 50 meetings) plus the last 100 calls, in its own store file `avalet-usage.json`. Reason: bounded size, no transcript text stored.
- Purposes are exactly suggestion / tracker / summary / screenshot; the key test and the wizard self-test count as suggestion. Reason: keep the four from the task.
- The checklist uses a non-streaming call. Reason: nothing is shown while it runs; exercises the non-streaming usage path.
- Briefing in live calls is cut at 3,500 characters with a note to the model; summary keeps the full text. Reason: CLOUD_TASK step 2.
- Overlay shows only this meeting's token count as small muted text; Settings shows this month and, in Advanced, a per-purpose breakdown. Reason: "never nag".
- Anthropic adapter accepts an optional base URL. Reason: lets the mock server and tests stand in for it; not exposed in the UI.
- Entitlement = Ed25519-signed token (`v1.<payload>.<sig>`) verified with `node:crypto`. Reason: no new dependency, small tokens, verification only needs a public key.
- `PRODUCTION_PUBLIC_KEY` is a placeholder whose private key was generated and discarded in this session. Reason: nobody (including this repo) can sign for it; the built-in provider stays off until the owner puts the real server key in `electron/billing/config.ts`.
- No private key is committed anywhere: MockBillingProvider and server-mock generate a key pair at startup; the app trusts a dev key only via `AVALET_BILLING_DEV_PUBKEY`. Reason: secrets hygiene; dev keys cannot leak.
- Offline grace is the token lifetime: `exp = iat + 72 h`, refreshed every 30 min while the app runs. Reason: one rule for both server and client; the proxy refuses expired tokens anyway.
- After the grace period the app shows a clear message and offers "Use my own key"; it does not switch to a paid own key silently. Reason: never spend the user's money without a click.
- The trial has no time limit (one-off 500,000 weighted tokens). Reason: CLOUD_TASK says "one-off", nothing about days.
- For a Pro user whose budget is used up, "Buy more tokens" opens the same checkout endpoint; the server decides whether that is a top-up. Reason: keeps the client gateway- and product-neutral.
- The client refuses Avalet calls itself when the access state says no (`AccessBlockedError`), in addition to the server's 402/403. Reason: no pointless requests; paywall shows at once.
- A paywall-refused live block is removed from the overlay and replaced by a banner (buy / own key / close). Reason: not an error the user caused.
- Checkout: browser page, then polling `GET /v1/entitlement` every 5 s for 15 min plus an "I have paid" button. Reason: no deep links or local servers needed.
- The in-process MockBillingProvider serves unit tests and UI work (`AVALET_BILLING=mock`, auto-pays after 1.5 s); E2E and contract tests use `server-mock/` over HTTP. Reason: both requested; only the HTTP path exercises the real contract.
- The install secret is stored only encrypted by the OS keychain; billing refuses to create an identity without it. Reason: same rule as provider keys.
- Key test ("test" button): one non-streaming call, 5 output tokens, metered as a suggestion; errors mapped to one human sentence in RU/EN in `electron/human-errors.ts`. Reason: CLOUD_TASK step 4.2.
- Wizard has exactly 4 screens (permissions, access, speech model, context); "Try it" expands inside screen 4. Every screen has "Skip for now". Reason: CLOUD_TASK max 4 screens.
- "Try it" makes one real suggestion call for a canned transcript with the chosen provider (metered as a suggestion); if it fails, the one-sentence reason plus a static example is shown. Reason: the user sees real value before the first meeting and learns early if access is broken.
- Simple main window: tabs Meeting and History plus a gear for Simple settings (access, speech, appearance, Advanced switch, run setup again, quit). History stays in Simple. Reason: past meetings are the user's own data; hiding them would read as data loss.
- Overlay opacity slider: on the overlay in both levels (rc.2), also in Settings in both levels. Reason: CLOUD_TASK_2 section 2, a control used during a meeting exists in Simple exactly as in Advanced. "Brightness" in CLOUD_TASK_2 is this opacity slider; its label stays "Opacity"/"Прозрачность" because that is what it changes.
- Simple overlay (rc.2) has the same controls as Advanced: Pause/Resume and End with text labels, Auto, opacity, screenshot, notes (the language button was removed from the overlay in CLOUD_TASK_4, see below), and all four 0.1 quick actions without a "More actions" fold; Simple only highlights "Clarifying question". The checklist panel still shows only when the live checklist is on or the meeting has an agenda or tasks. Reason: CLOUD_TASK_2, the owner could not find how to stop listening in rc.1.
- Plain buttons are now neutral; only the main action of a screen is `.primary` (filled). Reason: one visible primary action; white on the old accent fill failed AA (3.65:1).
- Colour tokens changed for WCAG AA, checked by an E2E contrast audit on every screen in both themes: `--accent-fill #0062cc`, dark `--accent-text #409cff`, dark `--danger-text #ff6961`, light `--muted #5c5c61`, light `--ok-text #17662b`, light `--danger-text #b8000f`, Auto/session "on" text `#003311`. Reason: quality bar in CLOUD_TASK step 4.
- Arrow glyphs (◀ ▶ ▸ ←) replaced by an SVG chevron. Reason: no arrow characters in UI strings.
- "How to fix" for a permission opens the matching System Settings pane directly (macOS). Reason: one button that fixes it.
- Advanced gets "Open the log folder". Reason: CLOUD_TASK lists logs under Advanced; the log never contains meeting text.
- No threshold controls were added to Advanced. Reason: none exist today as settings; adding them would add controls without a user need.
- E2E uses `@playwright/test` (Apache-2.0, dev dependency only) driving the built Electron app. Reason: `_electron.launch` gives real windows, IPC and screenshots under Xvfb.
- Test mode `AVALET_E2E=1`: fake sidecar and fake model download from `test/fixtures/`, a main-process fake capture feeding canned phrases (`electron/fake-capture.ts`), opened URLs written to a file, exports written to a folder, and on Linux only `safeStorage.setUsePlainTextEncryption(true)`. None of it is active in a normal launch.

- Unit and integration tests stay on `node:test` (no new test framework); integration drives `AppCore` handlers with the fake sidecar as a real child process and server-mock over HTTP. Reason: no dependency, same handlers IPC uses.
- Coverage via `node --experimental-test-coverage` (`npm run test:coverage`), no threshold. Reason: CLOUD_TASK "do not chase a number"; ledger, metering, access and meetings store are at 92-100%.

Verified by packing `--linux dir` here: the asar holds only dist-electron (no tests, no testing helpers), dist and package.json.
- No `minimumSystemVersion` set. Reason: the mic-only fallback works below macOS 13.2; the README states 13.2 for system audio.
- READMEs say plainly that "Avalet without keys" is not live yet and that the live checklist is unverified. Reason: CLOUD_TASK "honest limitations"; the server and the real signing key do not exist.
- market-check.md stays internal (docs/dev) and names other products; nothing user-facing does. Reason: CLOUD_TASK rule on competitor names in user-facing text.

## Mode tiers (CLOUD_TASK_3.md)

- Tier resolution: option (b) two plans now (Trial = free, interview, requirements, grooming; Pro = everything incl. review, demo, live checklist), plus option (c) an optional server-sent `features` list in the entitlement token that replaces the client's default table. Reason: no evidence yet for a third paid plan; (c) lets the server add one later without a client redesign. Details and alternatives in `mode-tiers-plan.md`; owner sign-off listed first in REPORT.
- Trial gets the analyst modes (requirements, grooming), not interview only as the owner proposed. Reason: a trial must show the core value to the core audience; the trial is already limited by its one-off budget. One-line switch in `PLAN_FEATURES`.
- `free` mode is available in every tier and is the fallback when a selected mode is not in the plan. Reason: no specialization to sell, and a plan must always leave a general mode.
- Live checklist gated as its own feature (Pro), separately from the modes; manual agenda marks and action points stay free. Reason: continuous background token cost and the clearest Pro argument; manual marks cost nothing and are the user's data.
- Gating is one pure function `featureGate()` in `electron/shared/tiers.ts` (shared by main and renderer) that returns "everything unlocked" first for own-key mode and for builds without a billing server, before any plan logic. Reason: CLOUD_TASK_3 section 1, structurally impossible to regress.
- Mode gating is a soft gate in an open source client; the server enforces only the budget. Written in the plan instead of building prompt inspection on the proxy. Reason: honest, and the proxy check would be trivial to evade.
- Mode boards: one overlay panel per mode (requirements, grooming, demo, review) that reads marker lines ("Требование:", "Срез:", "Отдельная задача:", "Риск:", "Отклонение:", "Попросите показать:", "Замечание:", "Решение:") from the finished suggestions of the current meeting (overlay history, cleared on End). Reason: zero extra model calls; demo and review already had markers, so they get the same treatment with a concrete reason; requirements and grooming prompts gained `Риск:`, `Срез:`, `Отдельная задача:`.
- The board appears only once it has an item, collapsed, with counts in its header; items are not stored in the meeting record or exports. Reason: no empty row costing overlay height; the summary already has the same headings and is the durable record.
- Grooming's second quick action asks about hidden work and size-changing risks but keeps the label "Risks?" with a tooltip. Reason: the longer label "Hidden work?" wrapped the quick-action row at 380 px (seen on the screenshot), and the guide's highlight rings are measured on that row.
- Mode boards and the grooming prompt apply in every access mode, own key included. Reason: they are per-mode product improvements, not a plan feature; "nothing new to look at" in CLOUD_TASK_3 section 1 is read as no lock, preview or upgrade UI.
- One `ModePicker` replaces the two mode selects (Simple home, ContextFields in Settings and the wizard); a locked option stays in the list with "(Pro)" / "(в Pro)" and opens the preview instead of switching (the controlled select snaps back). Reason: one place for the lock logic; a disabled option could not be clicked to learn what it is.
- `LockedPreview` is a modal card (Esc and a backdrop click close it) with the mode's help line, its board line, a real overlay screenshot, the plan line, the list of modes the plan includes, "Get Pro, price", "Not now", and "With your own key all of this is free" with the existing "use own key" navigation. It stays open during checkout and turns into "Done: ... is available" with "Use it" / "Turn it on". Reason: never a dead end; the own-key hint keeps the product honest about the free path.
- Live checklist lock: Advanced Settings shows a locked row instead of the switch; Simple Settings shows a checklist row only in Avalet mode (locked on the trial, a switch on Pro) so an own-key Simple screen is unchanged; the overlay shows a one-line locked row when there is no agenda, and a line inside the checklist panel when a manual agenda exists; the guide's checklist page names the plan when locked. Manual marks stay available. Reason: visible where the feature would be used without adding a second row next to the manual checklist.
- Preview images `src/renderer/assets/guide/mode-*.png` come from the screenshot mode (`AVALET_SCREENSHOT_DIR`), which now also renders one overlay per mode with its board open. Reason: CLOUD_TASK_3 asks for the guide's real-screenshot mechanism, not mockups.
- README mentions the mode boards but not which plan has which mode. Reason: the tier table is an unsigned pricing decision (private plan); the in-app lock text only appears once a billing server exists.
- E2E fixed for the how-it-works guide (rc.2 steps 8 to 11 added it after the last E2E update; CI was red on this branch before this task): tests that skip the wizard also mark the guide seen; the wizard and keyboard tests pass through the guide. ## CLOUD_TASK_4 (2026-09-28)

- Checklist fix = a separate verbatim `quote` with `speaker` and `at` on agenda items and action points, `note` stays the 12-word verdict. Reason: the dropped-remark bug is one slot doing three jobs (verdict, evidence, location); a longer note would crowd the overlay and still be a paraphrase with no location (`checklist-ux-research.md` section 2).
- Quotes are grounded locally (`locateQuote`: word stems of the quote in a run of 1 to 3 consecutive excerpt segments, at least 60%); a quote the transcript does not back is dropped; `at`/`speaker` come from the matched segment, not from the model. Reason: no invented quotes, and the location costs no prompt tokens or extra call.
- Tracker prompt gets one mode-specific line on which sentence is the evidence; the data shape is the same for every mode. Interview stays excluded from the tracker. Reason: per-mode findings differ in what to quote, not in structure; interview has no agenda to track.
- No third "decisions" list and no topic grouping. Reason: a decision is what closes an agenda item (verdict + quote), review's board already lists `Решение:` lines, and every extra list adds weight to the overlay.
- The summary merge keeps live quotes (the summary JSON has no quotes). Reason: otherwise ending the meeting would erase the evidence.
- Overlay checklist: folded row stays in its place (no layout jump), tray bounded to `32vh` (was 240 px = 43% of the default 560 px), one line per item with detail on click (one open at a time), add form and "Update now" behind a footer link. Reason: the suggestion keeps most of the height and full-size text (15 px vs 12 px).
- An open checklist or mode board folds itself when a new suggestion starts, unless the pointer is over it or someone is typing in one of its fields (a focused button, e.g. the header just clicked, does not count). Reason: a list opened a minute ago must not hide the new answer; someone working in it is not interrupted.
- Main window: the quote with speaker and a time button that scrolls the transcript to the matched segment and highlights it for 2.5 s; the protocol export puts the quote under its agenda item and under the action table. Reason: the main window and the file have the room; the overlay only shows who and when.
- Time next to a quote: `m:ss` from the meeting start in the overlay (`TrackerState.startedAt`, optional, added), `HH:MM:SS` in the main window and export (same as the transcript). Reason: compact in the overlay, consistent with the transcript elsewhere.
- One speech model: `SPEECH_MODELS = ["small"]`, the `SpeechModelName` type keeps `medium`/`turbo`. Reason: the smaller diff (cache layout code, fixtures and their tests stay as they are); every picker reads the list, so none can offer the others; a stored `medium`/`turbo` choice reads back as `small`. Files of a larger model downloaded earlier stay on disk (not deleted silently); noted in REPORT.
- The model picker became one readiness row (`SpeechModels`: not downloaded, downloading with progress and Cancel, partly downloaded with Continue, ready, error with Retry; Delete in Settings). Removed: row per model, "recommended" badge, "Use", the wizard's "other models later" line. Reason: CLOUD_TASK_4 phase 2.
- Early download starts at two points, whichever comes first, at most once per window (`lib/early-download.ts`): leaving the wizard's first screen, and the first-run how-it-works guide opening. Only a model in state `absent` (incl. partial, which resumes) is fetched; ready, downloading and failed are left alone. Reason: in the app the wizard comes before the guide, so the guide alone would start after wizard step 3, later than the task's intent ("as early as possible, instead of waiting for a wizard step"); the guide trigger covers a wizard that was skipped from outside. ## CLOUD_TASK_5 (review mode: spec sync)

- The design decisions for this task are numbered in `docs/dev/spec-sync-plan.md`; the lines below are the ones worth finding without opening it.
- The artifact is its own field (settings `artifactName`/`artifactText`, `Meeting.artifact`), not part of the briefing. Reason: the briefing is reference-only and capped in live calls; the artifact is the thing being edited and needs its full text at the end.
- Artifact cap 200,000 characters, refused above with a plain message; the cost is highlighted above 60,000. Reason: task rule; about 67 k tokens plus the transcript still fits large-context providers.
- Rough token figures use 3 characters per token everywhere (warnings, estimates). Reason: Russian text on current tokenizers is about 2.5-4 chars per token; 3 is the middle and matches the mock server.
- The document is stored in the settings store next to the briefing (`artifactText`, up to 200,000 chars), not in a separate file. Reason: same lifecycle as the briefing (set before Start, copied onto the meeting); electron-store rewrites a ~200 KB file only when the document changes.
- Only review meetings get a copy of the document (at Start, or when the mode is switched to review during the call). Reason: the document is used only there; other meetings should not keep a copy of it.
- Live calls in review mode get a code-built index (headings with numbers, first lines, the "Open questions" section verbatim), capped at 4,000 chars; a single top heading counts as the document title, not section 1. Reason: bounded cost per live call whatever the document size; section numbers the model and the decisions can share.
- A typed question that names a section ("раздел 3.2", "section 3.2", "п. 3.2") gets that one section's text (up to 4,000 chars) for that one question; automatic suggestions, quick actions and Process now never do. Reason: the task allows it as optional; it only happens on an explicit ask.
- Warning 1 (before the spend): the document field shows, as soon as a document is loaded and before Start, the rough tokens the document adds to each of the two end calls, what the index adds to each live suggestion, and the most a section question adds; highlighted above 60,000 chars. Reason: all three costs are decided by loading the document, so this is the moment to say so.
- The review board has three lists: remarks, proposals (new marker `Предложение:`), decisions. The live prompt adds one paragraph: section numbers from the index, `Предложение` for an unaccepted proposal, `Решение` only after clear agreement.
- Structured decisions are asked of the summary only for a review meeting that has a document; without one the review summary is exactly as before. Reason: decisions are the guide for updating the document, and the extra prompt and answer would otherwise raise every review summary with no warning (the End-screen warning is tied to the document).
- Decisions are checked in code after the summary (`electron/decisions.ts`): the quote is looked up in the transcript (`locateQuote`), `at`/speaker come from the transcript; an `accepted` decision without a found quote is kept, marked "words not found", and starts unchecked; an unknown status reads as `proposed`, never `accepted`; a section not in the document's index becomes `не определён`. Reason: the owner's trust rule gets a check that does not depend on the model following the prompt.
- Re-summarize: rows the analyst edited, added or deleted stay; a fresh decision with the same text (`sameTask`) as one of them is dropped; the rest of the previous summary's decisions are replaced. Deleted rows are kept hidden as tombstones.
- Decisions panel (review meetings, `DecisionsPanel.tsx`) sits between the actions row and the protocol text, in both levels; Simple folds "was / becomes" under "Details". Editable: checkbox, status, section (select from the document's headings), text, was, becomes; delete; add. "Who" is shown, not edited. Any change, the checkbox included, marks the row as done by hand. Reason: task list; the checkbox is the analyst's confirmation and must survive a new summary.
- A review meeting without a document shows one sentence and one button, "Attach document" (a file, same 200,000 cap), on the saved meeting. Reason: a forgotten file before Start is not a dead end; the next summary then returns decisions (with the warning below).
- Warning 2 (before the spend): under the meeting's actions row, a review meeting with a document always shows "this summary also reads the document: about N more tokens than usual", so it is visible before Summarize is pressed (the summary is started by hand after End, there is no automatic summary). Highlighted above 60,000 chars.
- "Update the document" = one call (usage purpose `artifact`, same balance as the summary, no new paywall) with the whole document and the checked decisions under short ids (`d1`...), mapped back in code. The model returns `{patches, skipped}` only; `electron/artifact-patch.ts` applies them: anchor exact (or with edge whitespace trimmed) and unique, CRLF documents matched and kept, whole-line delete takes its line break (and one of two surrounding blank lines), `insert_after` at a line end starts a new line, overlapping patches: the first wins. A patch for a decision that was not sent is not applied. Reason: the hard rule "the model never rewrites the document"; one bad patch never stops the others.
- The preview lists each good patch (now / after, checkbox, on by default) and, under "Not applied", bad patches, skipped decisions with the model's reason, and sent decisions the answer ignored. Apply = original + the checked patches, so unchecking and applying again undoes one; "Back to the original" drops the result. Proposal and result are stored on the meeting and reopen with it.
- Warning 3 (before the spend): next to "Update the document" the total rough figure; pressing it opens a confirmation that splits it (document, checked decisions, expected answer) with Send / Cancel. The call goes out only after Send. Figures are rounded ("about"), so the parts need not add up exactly.
- Exports: "Download document" writes `artifactResult.text` byte for byte (name "<document name> (updated).md"); "Copy document" puts the same text on the clipboard. "Download decisions" (enabled when a decision is checked, also before any update) writes the checked decisions with fixed headings (number and text, then section, status, was, becomes, who, quote with speaker and time) and the protocol's action points; headings follow the interface language. Reason: the owner's second workflow (decisions plus the original handed to another assistant) needs a stable, readable shape.
- The review summary with a document may answer up to 9,000 tokens (was 6,000 for every summary). Reason: a long decisions list must not cut the JSON tail, which would also lose the agenda marks and action points. The summary cost note counts about 1,000 tokens for the decisions in the answer.
- The guide's review image (`mode-review.png`, also the locked preview) regenerated from the screenshot mode with a proposal on the board; the mode help line for review mentions the document. No other guide page changed. Reason: task rule "update the review mode line only".

## CLOUD_TASK_6 (review fidelity)

- The owner's call is not reproduced from its text; every fixture is an invented "parcel" call. Causes are reasoned from the code and confirmed with synthetic tests (`docs/dev/review-fidelity-plan.md`). Reason: task rule, no real transcript text in the repo.
- Doubled lines: the live echo filter holds a mic segment 7 s, while the other channel is cut at up to 12 s and both channels queue on one recognizer; a clean copy arriving after the hold lets both copies through (test "a mic copy committed before the matching other segment arrives is not caught live"). Fix is a pass over the saved transcript, not a longer live hold. Reason: a longer hold delays every analyst line in the live view by up to 15 s; the saved record is what the summary, quotes and exports use.
- Unanswered questions (review): a rule block in the summary prompt, applied to every review summary, with or without a document; format `Вопрос без ответа: вопрос - задал кто - передан кому / без ответа (задан N раз) «цитата» (мм:сс)` under "Новые вопросы и риски"; "- нет" there only when nothing is open. Reason: findings 1 and 3; the owner's call may have had no document, so the rule cannot depend on one.
- Other modes: free, requirements, grooming and demo get the same rule as one sentence pointed at their existing "Открытые вопросы" heading; interview gets nothing (no such heading, and its summary is about the analyst's answers). Headings unchanged. Reason: task phase 1 "apply where it fits, do not change headings".
- The repeat count is a structured field `asked` (2 or more; 1 or unreadable is dropped) on an open decision, shown as a line in the checklist row. Reason: "repetition is the signal"; a count in free text could not be shown or tested.
- Terms (review): the text rule (pin key, value, one entry per what, repeat the speakers' example, else `не уточнено: термин, прочтение 1 или прочтение 2` and also a `Вопрос без ответа`) applies to every review summary; the `terms` JSON field exists only where the decisions list does (review with a document). When the wording and a later example disagree, that is `не уточнено` with both readings, not the example's reading. Reason: finding 2; "the model must not choose an interpretation" also rules out "the later example wins".
- Terms guard (`electron/shared/decision-terms.ts`): stems at a word start (so "ключ" finds "ключом" but not "включить"), RU and EN; "missing" = accepted + structure word in the text + empty terms; "unclear" = terms start with "не уточнено". Both show a mark and make the row start unchecked, like `ungrounded`. Reason: applying such a decision means choosing a reading nobody gave; the analyst pins the terms in the row (editable) and checks it by hand.
- The patch call carries `terms` and must skip a decision whose terms say `не уточнено` (or a structure change with nothing said about key or value) with the reason "термины не уточнены". Reason: the same rule must hold at the last step, where a guess would land in the document.
- The decisions `.md` gets a "Terms" line for every checked decision ("none" when empty). Reason: the file is handed to another assistant with the original; the terms are what it most needs. Fixed format kept (the line is always there).
- Second verification pass: adopted, on request only, in both levels: "Check against the quotes" in the decisions panel, cost on the button and again in a confirmation (Send / Cancel). Not automatic anywhere, so "off by default in Simple" holds and Advanced does not differ. It sends only accepted decisions with a quote, each with its quote and two transcript lines before and after (without them an example given a sentence later is invisible and the check would flag everything). Rough cost: about 300 tokens of instructions plus 250 per decision, so 5 decisions are about 1,600 tokens in and 400 out. Reason: the owner rule on spend; the check is cheap but it is a new request, so the person asks for it.
- The check can only lower, enforced in code (`applyCheck`): `not_supported` turns accepted into proposed and unchecks; `terms_unclear` writes `не уточнено: ...` into terms (the summary's pinned text stays readable after it) and unchecks; `ok` changes nothing. Rows the analyst edited by hand keep their content and only get the note; rows not sent are untouched; an unknown verdict is dropped, never read as ok. Metered as purpose `summary` (it is part of making the summary usable; no new purpose, no new counter row).
- Segment fields added now (`end`, `filtered`, `lowConfidence`, `quiet`) with `visibleSegments`, so the check already reads only the lines a person reads; the cleaning itself is phase 4.
- Contradictions with the briefing and participants: review mode only (every review summary, with or without a document); the other modes are unchanged. Reason: the task scopes itself to review plus generic transcript hygiene; extending participants to all modes would raise every summary's cost with a note on every End screen. Listed as an owner decision.
- Contradiction format `Расхождение с контекстом: в контексте X, на встрече Y - «цитата» (мм:сс)` under "Новые вопросы и риски"; the prompt forbids correcting one side by the other anywhere else in the summary.
- Participants come back as structured JSON (`named` / `inferred` / `third_party`, who, role), not as a heading. Reason: headings of the review protocol stay as they are, and a structured list can be checked in code: a name whose words (3+ letters, ending may differ) are not in the transcript is removed and a `named` entry becomes `inferred` (`groundParticipants`). The briefing is never a source of names. Empty list, empty line.
- The protocol's "Участники:" line (empty for every meeting before) is filled from that list: names, then "по ходу встречи: роли", then "третьи лица, не на встрече: ..."; the meeting screen shows the same line above the summary. Replaced on each new summary (no hand edits for it).
- Cost note: the End-screen note now shows for every review meeting, before Summarize: the rules add about 3,300 characters to the prompt and about 900 to the answer, about 1,500 tokens; with a document the figure adds the document as before. Other modes' one-sentence rule (about 370 characters, about 120 tokens, under 1% of a 30-minute summary) gets no note: a note on every summary for that would be noise. Listed as an owner decision because the owner rule is strict.
